# packages/portal-domain
- target_kind: shared domain/package contracts
- owned_paths: packages/portal-domain/**
- declared_responsibility: Portal route, DOM, navigation, service-state row, and dev command contracts.
- observed_responsibility: Owns route ids, descriptors, dev-tool URLs, route-group labels, parent portal content rows, and multiple panel intent/value maps that feed apps and proof surfaces.
- should_own: Route identifiers, route grouping, DOM ids, typed labels, dev-tool URL helpers, and small contract helpers.
- should_not_own: React rendering, runtime state, event transport, app-side shell logic, or backend/service behavior.
- allowed_dependencies: text-domain, schema-domain, agent-protocol-domain, and other pure contract packages.
- suspicious_dependencies: Large static content tables and row arrays that look more like app copy than shared contract data.
- expected_dependents: apps/portal, apps/parent-desktop, and any portal UI or proof surfaces consuming route and panel contracts.
- shared_contract_schema_usage: Strong use of Effect Schema for routes and branded dev URLs; the package is contract-first.
- duplicate_or_near_duplicate_shapes: PortalRouteLiteral, PortalRoute, and PortalRoutes mirror the same enum-like set; route context, route descriptor, and manage-lane switch logic overlap heavily.
- id_name_status_drift: Route ids, nav labels, and content labels are mostly aligned, but some static labels read like UI copy rather than a stable contract namespace.
- direct_import_vs_event_boundary: No event boundary ownership; app consumers should import these helpers instead of re-deriving route parsing or lane classification.
- event_bus_usage: None observed.
- logging_and_proof_chain_expectations: Pure contract package, so logging should stay out; proof-facing tokens and labels should remain typed and stable.

## Current Refresh Audit - 2026-06-19
- responsibility: Portal contract leaf, but the live source boundary is now mostly an `ActivityDigest` parser/read-model schema (`packages/portal-domain/src/activity-memory-graph.ts`) rather than portal route/DOM primitives.
- dependencies: Current source uses only `@ocentra-parent/agent-protocol-domain/contracts` and `@ocentra-parent/schema-domain/effect`; the manifest still advertises many broader domain deps that the live source does not justify.
- violations: Package README still claims broad portal/nav/service-state/proof ownership, while the only source file is a log-backed activity memory graph decoder; `tests/` and `proofs/` exist but are empty.
- duplicated_shapes: `PortalActivityMemoryGraphReadModel`, `PortalActivityMemoryGraphNode`, `PortalActivityMemoryGraphEdge`, and `PortalActivityMemoryGraphNodeId` are thin frontage around one canonical schema, and the node/edge/trace envelopes repeat `graphId`/`trace`/reference fields instead of sharing smaller primitives.
- barrel_reexport_shim_debt: No TS source barrels observed, but `packages/portal-domain/package.json` is a large export-map shim over many `dist/*.js` entrypoints, so consumers still meet a synthetic boundary rather than a compact source module set.
- schema_drift: README ownership and package description still read as portal-domain contracts, but the implementation is centered on `ActivityDigest` parsing and graph read-model validation; that is closer to activity/log contract ownership than portal UI contract ownership.
- event_log_proof_misuse: The parser consumes `AgentProtocolLogFields` and pulls `AgentProtocolDefaults.Field.ActivityDigest` from logs, which is a data-source boundary mismatch for a package documented as staying contract-first and proof-light; proof refs are described in docs, but there are no local proof artifacts.
- test_proof_structure_issues: `packages/portal-domain/tests/` and `packages/portal-domain/proofs/` are present but empty, so the schema filters and trace-citation rules have no package-local regression harness.
- dry_score_0_to_100: 49/100 because there is one real canonical parser/schema, but the package boundary is overclaimed in the README, under-supported by tests/proofs, and wrapped in a broad export-map shim with only one live source file.
- fix_recommendation: Keep portal-domain focused on route/DOM/nav contract primitives and move the activity-memory graph read-model parser to the owning activity/log contract package, with the portal package depending on it instead of hosting the logic itself.
- decouple_recommendation: Split the package boundary into a small portal contract leaf plus a separate activity-memory contract leaf; keep shared primitives in the current file only until the new owner exists, then thin the portal package to stable route and label helpers.
- blockers: No runtime blocker for this audit refresh, but boundary cleanup is blocked on deciding the correct owner for `ActivityDigest` and the graph read model.

- boundary_violations: The package stretches beyond contracts into substantial page/content data, especially rows and mode copy that look app-owned.
