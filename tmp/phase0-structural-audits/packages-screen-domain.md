## Current Refresh Audit - 2026-06-19
- responsibility: Screen capture/evidence/OCR/VLM/disclosure/readiness contracts are mixed with package aggregation and proof orchestration, so the package currently acts as a broad screen-domain hub instead of a narrow contract owner.
- dependencies: Allowed core shape is `schema-domain`, `evidence-domain`, `family-domain`, `policy-domain`, `event-domain`, and `lan-domain`, but the package also depends on `ai-domain`, `browser-domain`, and `enforcement-domain`, which makes the contract surface broader than the declared responsibility.
- boundary_violations: `packages/screen-domain/package.json` exposes a wildcard export map; `packages/screen-domain/src/screen-evidence.ts` is a large barrel; `packages/screen-domain/src/screen-intelligence-router.ts`, `packages/screen-domain/src/screen-evidence-detector-prompt-pack.ts`, `packages/screen-domain/src/screen-evidence-family-hub-routing.ts`, and `packages/screen-domain/src/screen-managed-browser-cdp-capture.ts` all re-export leaf shapes, which turns the package into an aggregation shim.
- duplicated_shapes: The same ready/disabled/blocked/approved/manualRequired pattern repeats across optional-visibility, live-view permission, live-view service session, capability status, and capability proof files; there is also repeated proof-row scaffolding across capability proof modules.
- barrel_reexport_shim_debt: High. The main debt is the `screen-evidence.ts` umbrella barrel plus smaller leaf re-export shims that keep adding new entry points instead of converging on explicit owners.
- schema_drift: High. The readiness vocabulary is fragmented across `productLiveViewReady`, `productModeReady`, `childDeviceCapabilityReady`, `childDisclosureReady`, `serviceSessionState`, `readinessState`, `blocked`, and `manualRequired`, which suggests overlapping but not identical schema intent.
- event_log_proof_misuse: No event-bus misuse is evident in this package, but proof helpers are reaching into `ai-domain` builders and the package mixes contract shapes with proof orchestration, which weakens the proof boundary and creates cross-domain coupling.
- test_proof_structure_issues: Proof logic is split across many leaf modules instead of one shared contract seam, so it is hard to see one canonical proof path or one minimal test surface for the shared readiness rules.
- dry_score_0_to_100: 79
- dry_score_reasons: Strongest drag is the repeated readiness schema family and broad barrel/re-export pattern; moderate drag comes from cross-domain dependencies and proof-helper coupling; score is still above average because the package is mostly contract-level code, not runtime behavior.
- fix_recommendation: Extract a shared optional-visibility/live-view readiness core, move repeated ready/disabled/blocked/approved/manualRequired fields onto that core, and replace wildcard/umbrella exports with explicit leaf entrypoints.
- decouple_recommendation: Split the broad `screen-evidence` hub into smaller ownership slices so evidence, router, live-view readiness, and optional-visibility proofs can evolve independently without a package-level aggregation shim.
- blockers: This refresh is audit-only; the exact consumer map and all downstream proof/test impacts were not re-traced in this pass, so any fix plan should re-verify dependents before changing public exports or schema names.
