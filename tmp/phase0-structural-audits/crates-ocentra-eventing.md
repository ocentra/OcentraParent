- Schema drift: proof/document strings in `README.md` and `src/compatibility.rs` point at output roots that are not present in this checkout, so the crate is describing proof state that is not locally materialized; contract/topology/compatibility tables can diverge because they each encode their own row shapes.
- Event/log/proof misuse: no runtime logging calls were present, which is good; the misuse is that proof claims are embedded as hardcoded paths and narrative text rather than a single shared proof manifest, and the README treats absent proof roots as expected artifacts without a local verifier.
- Test/proof structure issues: the test tree is split into contract, unit, integration, journal replay, version skew, and support folders, but the proof story is fragmented across README prose, examples, and hardcoded artifact paths; there is no single source of truth linking crate claims to generated proof outputs in this checkout.
- DRY score: 58/100. The crate is strongly typed and mostly boundary-clean, but it repeats report/state counting, markdown rendering, and proof metadata across several modules; the missing proof roots and duplicated row/table builders lower the score.
- Fix recommendation: factor a shared snapshot/report helper for queue, request, shutdown, and clear counts; factor a shared markdown table renderer for contract/topology/compatibility docs; move proof-path declarations into one manifest module and have docs/examples consume it.
- Decouple recommendation: keep runtime state transitions in `bus`, `queue`, `journal`, and `request`, and keep documentation/proof rendering in `compatibility`, `contract_registry`, and `topology` as read-only consumers of shared snapshot structs.
- Blockers: generated proof roots referenced by the README and compatibility matrix are absent here, so local verification of the proof story is incomplete; I did not inspect beyond the crate boundary and its nearest docs by design.
