## Current Refresh Audit - 2026-06-19

- responsibility: Typed local agent-service API route and command contract manifest. This package should stay contract-only and own route IDs, path schemas, manifest records, and command lookup helpers.
- dependencies: Clean dependency shape overall. The live package still depends only on `@ocentra-parent/agent-protocol-domain` and `@ocentra-parent/schema-domain`, which matches the contract boundary.
- violations: No direct runtime/service boundary violation observed in the live source. The main structural issue is stale package surface: `package.json` still exports `./package-info`, but `apps/local-api/src` only contains `local-api.ts`, so the source/export pairing is drifting.
- duplicated_shapes: Route IDs, transport values, command names, and manifest entries are repeated across the manifest and helper lookups in `apps/local-api/src/local-api.ts`. That duplication is acceptable only if the manifest remains canonical.
- barrel_re-export_shim_debt: No TS barrel/re-export pattern was seen in the inspected surface. The only shim-like helper is `localApiWebSocketRoute()`, which is fine as a fallback resolver but should not spread into a second source of truth.
- schema_drift: `local-api.ts` still models the route contract directly, and the manifest route IDs/transport values look aligned with the README description. The drift risk is the missing source for the exported `./package-info` entry, not the schema itself.
- event_log_proof_misuse: None observed. This package is contract metadata only, and the live source does not introduce event/log/proof plumbing.
- test_proof_structure_issues: `apps/local-api/tests/` is empty in the current checkout, so the package has no visible contract proof coverage despite having `test` and `type-check` scripts. That makes the boundary easy to regress silently.
- dry_score_0_to_100: 79. The package is still focused and mostly contract-only, but the score drops for the stale export/source mismatch, the lack of local proof tests, and the repeated route/command shapes that need a single canonical manifest.
- fix_recommendation: Reconcile the package export surface with the real source layout, then keep the manifest as the only canonical route table. If `package-info` is still needed, restore its source; otherwise remove the export.
- decouple_recommendation: Keep the manifest data separate from any future service implementation and avoid adding runtime behavior into `apps/local-api`. If more route variants appear, move shared schema helpers into a lower contract package instead of duplicating route logic here.
- blockers: No hard blocker for audit refresh. The only blocker to stronger confidence is the missing `src/package-info.ts` source behind the existing export and the absence of visible tests.
