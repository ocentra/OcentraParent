## Current Refresh Audit - 2026-06-19

- responsibility: `scripts/test` is the repo's standalone proof and smoke-script forest. It owns narrow validation entrypoints, local process helpers, and proof scripts that exercise portal, agent, browser, and command-envelope boundaries.
- dependencies: Strong dependence on `node:child_process`, temporary directories, process cleanup helpers, local dev config helpers, WebSocket smoke utilities, and imported contract schemas such as `AgentEventEnvelopeSchema`.
- violations: No product-boundary violations in the strict sense, but the folder is still acting as a catch-all for adjacent proof concerns. Several scripts directly assemble subprocess commands, environment envelopes, and cleanup flows instead of going through a smaller shared harness.
- duplicated_shapes: Repeated spawn/wait/timeout/cleanup patterns, repeated WebSocket session setup, repeated local HTTP health polling, repeated dev-log assertions, and many near-identical `*-proof.mjs` wrappers around slightly different assertions.
- barrel_reexport_shim_debt: No obvious barrel/re-export problem in this boundary, but there is shim-like frontage debt. The one-off proof wrappers behave like thin facades over a few recurring harness patterns, so the duplication is structural rather than export-based.
- schema_drift: Mixed contract hygiene. Some scripts consume typed schemas or shared helpers, but other proof entrypoints still construct JSON payloads and command envelopes inline. The envelope shape is duplicated across the WebSocket smoke path and sibling proof scripts.
- event_log_proof_misuse: Proof scripts are correctly using events and logs as validation surfaces in many cases, but the logging/proof contract is uneven. Some checks assert dev-log output or event milestones directly, while other wrappers only validate a local side effect without a common milestone contract.
- test_proof_structure_issues: The boundary mixes low-level harness helpers, focused proof scripts, and broader orchestration entrypoints in one directory. That makes ownership diffuse and makes it easy for new proof topics to accrete another near-duplicate file instead of extending a shared harness.
- dry_score_0_to_100: 35
- dry_score_reasons:
  - The folder is large and heterogeneous, so ownership is blurred.
  - Repeated process/WebSocket/cleanup scaffolding shows low reuse of common core.
  - Envelope and milestone shapes are duplicated enough to create drift risk.
  - There is some shared helper usage, so the boundary is not completely fragmented.
  - Existing proof scripts are mostly purpose-built, but many are thin wrappers rather than independently owned logic.
- fix_recommendation: Extract a small shared proof harness for spawn, wait, cleanup, health polling, and WebSocket session setup. Then migrate the highest-frequency smoke/proof families onto that harness before touching long-tail wrappers.
- decouple_recommendation: Split the broad forest into tighter sub-ownership by boundary type, such as process helpers, WebSocket smoke, portal smoke, source-shape/guard tests, and app-domain proof packs. Keep the path names aligned to the owning boundary so future scripts do not inherit the catch-all shape.
- blockers: No blocker to documenting the refresh. The only practical blocker to deeper DRY cleanup is the scale of the existing forest: this directory is already a large, mixed proof surface, so consolidation needs a measured pass rather than a single mechanical rewrite.
