- dry_common_core_candidates: Extract a smaller child-runtime contract surface for gate decisions, event type constants, and flow report shapes; align Rust gate state definitions with the TS domain package instead of maintaining parallel copies.
- dead_frontage_or_shims: `lib.rs` functions mostly as a frontage shim over private modules plus re-exported protocol/core symbols.
- proposed_fix_packets: Remove the root barrel, make module ownership explicit, and move repeated decision-state vocabulary into a shared child-runtime contract module before more flows accrete here.

## Current Refresh Audit - 2026-06-19

- Responsibility: `crates/child-runtime` is the child-side orchestration boundary for runtime preflight, tracking, policy-control, and child-domain event flows; the crate should own orchestration only, not a second copy of shared contract vocabulary.
- Deps: the crate fans out across `ocentra-app-core`, `ocentra-app-game-core`, `ocentra-browser-core`, `ocentra-child-ai-core`, `ocentra-child-notification-core`, `ocentra-child-policy-core`, `ocentra-child-enforcement-core`, `ocentra-entitlement-core`, `ocentra-eventing`, `ocentra-family-identity-core`, `ocentra-lan-core`, `ocentra-network-core`, `ocentra-parent-agent-protocol`, `ocentra-policy-control-core`, `ocentra-provisioning-core`, `ocentra-remote-access-core`, `ocentra-screen-core`, `ocentra-screen-live-view-core`, `ocentra-storage-custody-core`, and `ocentra-tracking-core`, so it is still a convergence point rather than a narrow runtime façade.

- Duplicated shapes: `crates/child-runtime/src/runtime_gate.rs` defines local `ChildRuntimeStartState`, `ChildRuntimeManualReviewState`, `ChildRuntimePreflightInput`, and decision/event wrappers that mirror sibling domain vocabulary; `crates/child-runtime/src/tracking_runtime_flow.rs`, `crates/child-runtime/src/tracking_config_update_flow.rs`, and `crates/child-runtime/src/child_domain_runtime_flow.rs` all repeat the same subscribe-state-publish-report pattern; `crates/child-runtime/src/event_flow_scaffold.rs` is a shared helper for repeated option/vector state handling.
- Barrel/reexport/shim debt: no current Rust `pub use` barrel showed up in the crate, but the root module is still a broad shim because it exposes the whole orchestration surface at once and leaves the actual ownership split hidden behind module names; the parallel TS contract surface in `packages/child-runtime-domain/src/child-runtime-gates.ts` and `packages/child-runtime-domain/src/child-domain-runtime-events.ts` shows the same contract family already exists elsewhere.
- Schema drift: `crates/child-runtime/src/runtime_gate.rs` still carries Rust-side gate and decision naming that diverges from the TS domain package shapes under `packages/child-runtime-domain/src/child-runtime-gates.ts`; the drift is mostly naming and boundary placement, not an obvious broken field mapping.

- Score: 51/100, high risk; the score is still driven by frontage breadth, duplicated contract shapes, and the amount of orchestration bundled into one crate.
- Fix recommendation: split the shared child-runtime contract vocabulary out of `crates/child-runtime/src/runtime_gate.rs` first, then narrow `crates/child-runtime/src/lib.rs` to a thinner orchestrator entrypoint and keep the flow modules focused on event wiring only.
- Decouple recommendation: move shared child-runtime gate/decision/event naming into `packages/child-runtime-domain/src/child-runtime-gates.ts` and `packages/child-runtime-domain/src/child-domain-runtime-events.ts` as the canonical contract boundary, then let the Rust crate adapt to those contracts instead of re-declaring parallel shapes.
- Blockers: the immediate structural blocker is the shared contract split, not a syntax failure; the report/process blocker from this refresh was the `hub:report` details payload shape, which needs to be passed as one structured block for `STARTED`/`DONE` state reporting.
