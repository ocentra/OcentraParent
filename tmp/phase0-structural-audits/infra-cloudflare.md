## Current Refresh Audit - 2026-06-19

- responsibility: `infra/cloudflare` is the shared Cloudflare control-plane runtime for Parent, owning the worker entrypoint, route manifest, auth boundary, redaction, local bindings/read-model support, and queue/DO orchestration.
- dependencies: allowed dependencies are still narrow and mostly correct, but the runtime now leans on `packages/billing-domain` schemas plus local worker/DO/queue helpers, and the main worker also depends on the local read-model layer to emulate most runtime behavior.
- violations: the main violation is still a god module in `infra/cloudflare/src/index.ts` that mixes routing, auth, response shaping, idempotent write envelopes, queue dispatch, DO coordination, webhook handling, admin actions, and manual-required fallback responses in one file.
- duplicated shapes: request body aliases, hosted-session response builders, idempotent-write envelopes, queue-message payloads, manual-required responses, and route/handler metadata are all repeated across `src/index.ts`, `src/routes.ts`, `src/billing-binding-read-model.ts`, and the tests instead of being factored into smaller shared route-family modules.
- barrel/re-export/shim debt: I did not find TS/JS barrel or re-export debt inside `infra/cloudflare`; the debt here is scaffold debt instead, mainly the empty `src/*/README.md` directories plus the thin `src/testing.ts` harness that wraps the worker, fake DOs, and queue recorders rather than providing first-class runtime modules.
- schema drift: route keys, handler keys, auth states, and proof family names are mostly aligned, but the large dispatch file makes it easy for `src/routes.ts`, `src/index.ts`, and the billing-domain schemas to diverge when one path changes without a corresponding helper split.
- event/log/proof misuse: redaction is present and should stay, but logging, dead-letter assembly, manual-required payloads, and proof-ish runtime responses are still assembled in the worker instead of being isolated to dedicated boundary helpers or explicit proof artifacts.
- test/proof structure issues: the test surface is broad, but it still reads like a mix of runtime validation and proof stand-ins; the `src/testing.ts` harness fabricates DOs and queues, integration and contract tests lean on the same concentrated worker, and there is no sign in this pass of a canonical proof bundle that clearly separates runtime truth from proof truth.
- DRY score: `41/100`
- DRY score reasons: score is better than a pure scaffold because the route manifest, auth boundary, redaction, and local read-models are real, but it stays low because the same mutation, queue, and response patterns repeat across one giant worker and a large read-model file, while the scaffold directories still behave like frontage rather than owned modules.
- fix recommendation: split `src/index.ts` by route family, extract a reusable idempotent-write helper, move queue/dead-letter assembly into its own helper, and pull the placeholder/contract-shaped responses out of the worker core so the entrypoint only routes and delegates.
- decouple recommendation: decouple the runtime into explicit worker, auth, queue, DO, and read-model modules, then let tests depend on those boundaries instead of on the full worker plus the `src/testing.ts` harness.
- blockers: the current blocker is architectural concentration rather than missing syntax; until the worker and read-model code are split, the same route/mutation logic will keep duplicating across files, and the scaffold-only directories under `src/` will continue to masquerade as owned implementation areas.
