- score: 5/10.
- fix recommendation: split the package into clear leaves and remove the TS re-export barrel from `network-control-catalog.ts`; keep the contract schemas, flow schemas, catalog schema, seed data, and metadata helpers as separate ownership units, and add a small shared network primitive module only if the repeated evidence/ref/status vocabulary keeps growing.
- decouple recommendation: separate the derived control-catalog materialization path from the evidence/flow contract package boundary if this package keeps absorbing more UI-ready policy material; the likely split point is `network-control-catalog.*` versus `network-contracts.ts` and `network-flow.ts`.
