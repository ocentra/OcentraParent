## Current Refresh Audit - 2026-06-19
- current responsibility: parent-runtime orchestration plus two embedded flow engines, one for tracking config updates and one for policy-control delivery; it still owns dispatch routing, request packaging, and parent-visible flow reporting.
- dependencies: `ocentra-child-runtime`, `ocentra-eventing`, `ocentra-parent-agent-protocol`, `ocentra-policy-control-core`, `serde`, and `tokio` for async tests.
- boundary violations: the crate now owns both parent dispatch decisions and full event-bus-backed flow orchestration; `tracking_*` modules still blur parent-runtime ownership into tracking-domain behavior, and `policy_control_update_flow.rs` pushes further into policy-delivery sequencing than a thin runtime bridge.
- duplicated shapes: `tracking_config_update_flow.rs` and `policy_control_update_flow.rs` both build bus/state/report scaffolding, publish a root request, fan out to follow-up events, and capture final read-model state; `tracking_dispatch.rs` and `policy_control_dispatch.rs` both define typed dispatch ids, domain events, routing helpers, and idempotency keys.
- barrel/reexport/shim debt: no `pub use` or JS/TS re-export debt is present; `src/lib.rs` is only a `pub mod` surface, so the debt is module sprawl rather than shim indirection.
- schema/contract drift: no obvious schema-version mismatch surfaced in this pass, but `tracking_config_update_flow.rs` still mixes parent-runtime dispatch with `network_flow` and tracking-contract constants, and the policy-control path couples delivery-state policy to parent runtime flow logic instead of a narrower contract adapter.
- event bus/log/proof misuse: the crate is intentionally bus-driven, but there is still no explicit logger/proof-chain surface in these runtime modules; the proof burden is mostly indirect through event subscriptions and request completion, which makes runtime observability thin if these flows expand further.
- test/proof structure issues: tests live as large integration-style scenarios under `tests/unit/*`; `tests/unit.rs` is only path-module wiring, and `tests/unit/runtime_dispatch.rs` is a kitchen-sink file that mixes dispatch, check-in, and tracking-config assertions instead of a smaller helper-driven proof layout.
- current DRY score: 67/100.
- fix-pass recommendation: extract a shared runtime dispatch helper for request metadata/idempotency and a shared event-bus flow skeleton for the two large update flows before adding any new parent-runtime behavior.
- decouple-pass recommendation: split the policy-control orchestration and the tracking config orchestration out of `parent-runtime-core` once the shared helper exists, leaving this crate focused on parent-side dispatch and typed event contracts.
- sequencing/blockers: start with the shared helper and test helper cleanup, then peel off one flow at a time; the main blocker is that both update flows currently depend on the same parent-runtime bus/state/report shape, so untangling them will require coordinated test reshaping.
