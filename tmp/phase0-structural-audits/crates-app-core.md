# crates/app-core
- target_kind: Rust core crate for app runtime decision translation and child-domain event wrapping.
- owned_paths: `crates/app-core/src/lib.rs`, `crates/app-core/src/runtime_decision.rs`, `crates/app-core/tests/unit.rs`, `crates/app-core/tests/unit/*.rs`
- declared_responsibility: convert app observation intent into child-domain observed/evidence/policy event contracts and record app runtime decisions.
- observed_responsibility: evaluates app capability, foreground, and classification state into decision state, wraps child-domain event helpers, and verifies the mapping with unit tests.
- should_own: app-specific observation intent mapping, runtime decision enums, app event wrappers, and contract-focused tests for the app child-domain path.
- should_not_own: shared generic runtime engines, unrelated domain logic, UI/runtime orchestration, logging policy, or cross-domain contract families.
- allowed_dependencies: `ocentra-eventing`, `ocentra-parent-agent-protocol`, `serde`, local `runtime_decision` module.
- suspicious_dependencies: no obvious extra dependency; the main concern is API shape, not the dependency list.
- expected_dependents: app runtime callers, app-side proof/tests, and any parent-side code that needs app observation/event translation.
- shared_contract_schema_usage: `ChildDomainObservedEvent`, `ChildDomainObservedEventProfile`, `ChildDomainEvidenceRecordedEvent`, `ChildDomainAiAnalysisRequestedEvent`, `ChildDomainPolicyEvaluationRequestedEvent`, `ChildRuntimeDomain::App`.
- duplicate_or_near_duplicate_shapes: near mirror of `crates/app-game-core` with renamed enums, ID wrappers, decision logic, and recorded-event construction; both crates share the same text-id macro pattern and event-contract pattern.
- id_name_status_drift: names are domain-correct, but the state machine is almost identical to the game crate, so semantic drift is likely if one side changes without the other.
- direct_import_vs_event_boundary: direct construction of child-domain events is the only boundary here; there is no event bus layer. The `lib.rs` public re-export leaks `runtime_decision` internals across the crate boundary.
- event_bus_usage: none observed.
- logging_and_proof_chain_expectations: no logging or proof-chain instrumentation is present; callers that exercise this crate should own correlated proof milestones if the runtime path is validated elsewhere.
- boundary_violations: `pub use` re-export from `lib.rs` violates the repo no-reexports rule and turns the crate root into a frontage surface.
- dry_common_core_candidates: extract a shared runtime-decision template for app/game child-domain translators, parameterized by domain labels, event type strings, and ID prefixes.
- dead_frontage_or_shims: `lib.rs` is mostly frontage around `runtime_decision`; the public re-export surface is thinner than the underlying implementation.
- proposed_fix_packets: remove the crate-root re-export barrel, then factor the shared runtime-decision mechanics into a reusable core or macro-driven template with domain-specific constants.
- severity: high
- confidence: high
- evidence_paths: `crates/app-core/Cargo.toml`, `crates/app-core/src/lib.rs`, `crates/app-core/src/runtime_decision.rs`, `crates/app-core/tests/unit.rs`

## Current Refresh Audit - 2026-06-19
- responsibility: `crates/app-core` owns app-specific observation intent translation, runtime decision evaluation, and child-domain event wrapping for app runtime decisions.
- dependencies: the crate is narrow and mostly depends on `ocentra-eventing` plus `ocentra_parent_agent_protocol`; the main coupling is to shared child-domain contracts, not to local infrastructure.
- boundary_violations: no new crate-root re-export barrel is present in `crates/app-core/src/lib.rs`, so the earlier frontage concern has been reduced; the remaining boundary risk is semantic overlap with the game core and the fact that the crate still constructs shared child-domain events directly.
- duplicated_shapes: the app decision pipeline is still a close mirror of `crates/app-game-core`, including intent selection, observed-profile construction, evidence recording, and optional AI/policy handoff paths.
- barrel_reexport_shim_debt: current `lib.rs` is module-frontage only (`pub mod runtime_decision`), so there is no active `pub use` shim debt in this crate; the remaining debt is duplication between the crate root and `runtime_decision` helpers.
- schema_drift: the event contract is explicit and typed, but `AppRuntimeDecisionRecordedEvent` and the intent/state enums remain a local translation layer that can drift from sibling runtime translators if the mirrored shape changes independently.
- event_log_proof_misuse: no logging, telemetry, or proof-chain misuse was observed in this crate; it is a pure translator and does not emit runtime logs or proof milestones itself.
- test_proof_structure_issues: tests are expected to stay contract-focused and local to the translator path; the structural risk is that coverage can become shape-replication rather than behavior-differentiation because the module is small and mirrored.
- dry_score_0_100: 64. The crate is cleanly scoped and no longer carries a barrel re-export violation, but it still duplicates a near-isomorphic child-domain translation pattern that is likely to diverge from `crates/app-game-core` unless the shared mechanics are extracted.
- fix_recommendation: keep the app-specific enums and event IDs in place, but extract the common child-domain translation flow into a shared helper/template so the app and app-game translators stop hand-maintaining the same state-machine skeleton.
- decouple_recommendation: separate the local runtime decision semantics from the shared child-domain event construction by pushing the repeated observed-profile/evidence/handoff wiring into one reusable internal primitive.
- blockers: no immediate blocking defect was found in the crate surface; the main blocker to further simplification is the need to preserve app/game semantic names while avoiding shared-contract drift.
- exact_likely_paths: `crates/app-core/src/lib.rs`, `crates/app-core/src/runtime_decision.rs`, `crates/app-core/tests/unit.rs`, `crates/app-game-core/src/lib.rs`, `crates/app-game-core/src/runtime_decision.rs`.
