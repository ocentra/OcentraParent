## Current Refresh Audit - 2026-06-19
- Responsibility: production desktop shell wrapper for the parent portal; it should own Tauri wiring, packaging, and runtime-boundary proof only.
- Dependencies: `apps/parent-desktop/package.json` uses `@tauri-apps/api`, local `@ocentra-parent/portal`, and `@tauri-apps/cli`; `src-tauri/Cargo.toml` uses `tauri`, `tauri-build`, `serde`, and `ocentra-parent-agent-protocol`; `tauri.conf.json` wires portal dev/build URLs and dist output.
- Violations: no hard boundary break observed, but the proof frontage crosses into service, packaging, update, signing, store, and support semantics in one serialized response object.
- Duplicated shapes: `ParentDesktopPlatformProofState` repeats `route_state`/`route_source_state`, `lan_ai_provider_state`/`degraded_source_state`, and mirrors `service_state` into `activity_adapter_state`; several fields are constant mirrors instead of independently owned state.
- Barrel/re-export/shim debt: no TS/Rust barrel or re-export chain was observed in this app slice; the main debt is the large `parent_platform_proof_state` serialized shim, which behaves like a facade over shell truth.
- Schema drift: the DTO is highly stringly and constant-backed, so any constant rename or contract tweak can diverge across `lib.rs`, `tauri.conf.json`, and the app README unless the proof shape is split.
- Event/log/proof misuse: proof is fetched through a direct Tauri command plus socket probe, with no event bus or log correlation; the object is being used as both runtime check and support-readable status sheet.
- Test/proof structure issues: tests in `src-tauri/src/lib.rs` assert a long list of individual fields one by one, duplicating the production mapping; the second test only proves the socket-connect branch and does not exercise the command entrypoint or serialization boundary.
- DRY score: 74/100. Reason: the shell boundary is still clean, but the proof DTO and its tests repeat the same contract vocabulary across many constant-backed fields and derived aliases.
- Fix recommendation: split `ParentDesktopPlatformProofState` into smaller concern-shaped records or nested proof groups, then move assertions to table-driven checks keyed by shared constants.
- Decouple recommendation: separate connectivity/runtime probe data from packaging/release/support diagnostics, and keep `tauri.conf.json` and the README aligned with one canonical shell contract section.
- Blockers: no functional blocker; the main risk is contract drift if any proof constant or field name changes without a companion shape split.
- Exact likely paths: `apps/parent-desktop/src-tauri/src/lib.rs`, `apps/parent-desktop/src-tauri/tauri.conf.json`, `apps/parent-desktop/package.json`, `apps/parent-desktop/README.md`.
