## Current Refresh Audit - 2026-06-19

- responsibility: still a catch-all production contract package for release, support, public-status, incident, publication, and sync-export proofs; the package manifest exports the entire `src/*` surface and only a package-info facade.
- dependencies: `@ocentra-parent/family-domain` and `@ocentra-parent/schema-domain` are the only declared runtime deps; the current source shape leans heavily on shared schema helpers and family references rather than a deeper domain split.
- violations: the package keeps runtime-adjacent states inside contract/proof schemas (`implemented`, `executed`, `published`) while trying to assert non-claim boundaries; that is honest enough for proofing, but it is still an oversized ownership bucket.
- duplicated_shapes: repeated `row + proof + summarize` patterns appear across `family-web-route-map.ts`, `production-release-public-docs-status.ts`, `public-support-contact-status-proof.ts`, and `parent-owned-sync-export.ts`; the same guard/filter/summarize structure is replicated with different nouns.
- barrel/re-export/shim_debt: `package.json` exposes a broad `./*` export surface; `src/package-info.ts` is a tiny frontage file; `production-release-public-docs-status.ts` and `public-support-contact-status-proof.ts` both re-export their `*-values` modules, so the package has multiple thin shims instead of a single owning boundary.
- schema_drift: `family-web-route-map-values.ts` and `family-web-route-map.ts` show contract-only route states, while `production-release-public-docs-status.ts` and `public-support-contact-status-proof.ts` encode nearly identical state ladders with different labels; the shared schema grammar is drifting toward copy-paste specialization.
- event_log_proof_misuse: no explicit event bus is present, but the proof files repeatedly model execution, publication, upload, runtime, and handoff claims as if they were operational events; that is acceptable only because the schemas also block those claims with filters and non-claims.
- test_proof_structure_issues: the package has a single visible unit test at `packages/production-domain/tests/unit/family-web-route-map.test.ts` and many proof-oriented test folders are still empty `.gitkeep` shells; the test layout does not mirror the breadth of the proof surface.
- dry_score_0_to_100: 47
- dry_score_reasons: breadth is the main problem, not missing correctness; there is heavy repetition across proof families; the shared schema layer is used well; explicit non-claim filters keep the package honest, but they do not reduce duplication or ownership overlap.
- fix_recommendation: split the current package into smaller ownership clusters around the existing proof families, starting with the route-map/public-web slice, the public-docs slice, the public-support-contact slice, and the sync-export slice.
- decouple_recommendation: move repeated `row/proof/summarize` helpers into local common modules per slice, then stop exporting all `src/*` entrypoints from the package root.
- blockers: no README was present under `packages/production-domain`, so intent is carried entirely by code; the package still has broad `src/*` exports, so any real DRY cleanup will need boundary edits rather than another audit pass.
