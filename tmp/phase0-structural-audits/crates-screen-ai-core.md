## Current Refresh Audit - 2026-06-19
- responsibility: Own the screen AI pipeline contract layer: trigger classification, pipeline input/decision types, recorded decision events, and the evaluation-to-record transformation.
- dependencies: `ocentra-evidence`, `ocentra-eventing`, `ocentra-policy-control-core`, and `serde`; the dependency set is narrow and intentional, with no runtime/event bus dependency beyond contract types.
- violations: `src/lib.rs` is a full `pub use` facade instead of a narrow module surface; the crate keeps a macro-generated branded-id helper that mirrors sibling screen-domain ID patterns; the exported API is broader than the crate boundary implies.
- duplicated_shapes: `ScreenAiPipelineEvaluationRequestedEvent` and `ScreenAiPipelineDecisionRecordedEvent` mirror a request/record pair; the text-id macro repeats the same parse/Display/From logic three times; the `Input` and `Decision` structs follow the same contract-shape pattern used in other screen crates.
- barrel_reexport_shim_debt: `src/lib.rs` is a pure re-export shim today. It hides the real owner module, broadens the public surface, and creates a frontage file that conflicts with the no-barrels rule.
- schema_drift: Event type strings and schema versioning are hard-coded in `screen_ai_pipeline.rs`; there is no sibling compatibility layer or version migration path in this crate. The risk is not an internal mismatch today, but future drift if the event names or `SchemaVersion::new(1)` need to change.
- event_log_proof_misuse: No runtime logging or proof materialization lives in the crate, which is correct for a contract layer. The weak point is that the proof boundary is mostly empty scaffolding in `tests/`, so contract evidence is limited to one unit path and string assertions.
- test_proof_structure_issues: Real tests are concentrated in `tests/unit/pipeline_decision.rs` behind `tests/unit.rs`; the rest of `tests/` is placeholder directories. There are no focused parse-failure, idempotency, or serialization-roundtrip tests for the text IDs or event contracts.
- dry_score_0_to_100: 40. The score is dragged down by the public re-export shim, repeated branded-id construction, mirrored request/record event shapes, and thin proof coverage. It is not lower because the dependency set is small and the core decision function itself is compact.
- fix_recommendation: Remove the `pub use` facade, make the module exports explicit, and replace the local branded-id macro with a shared typed helper only if a second consumer actually needs it. Add narrow contract tests for parse failure, idempotency key shape, and event contract stability.
- decouple_recommendation: Keep decision logic, event-contract construction, and test/proof layout separated. If the crate expands, split the pure pipeline decision from the event-record helper layer so the API surface stays narrow and ownership stays obvious.
- blockers: No blocker for this refresh. Cross-crate duplication against `crates/screen-core` is still an inference from the earlier audit, not a fresh read in this target scope.
