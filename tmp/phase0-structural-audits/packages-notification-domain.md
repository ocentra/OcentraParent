- event/log/proof misuse: there is no explicit event-bus or logging misuse here; the main misuse risk is treating proof fixtures as runtime evidence, because several rows carry runtime-shaped claim flags and payload previews that look executable.
- test/proof structure issues: coverage is organized as one test file per boundary/proof family, but most tests mirror the fixtures rather than exercise a shared contract spine; `package-info.test.ts` only verifies identity, so it does not defend the package surface from drift.
- score: 60/100.
- fix recommendation: split the shared contract spine from the proof fixtures, consolidate common state catalogs and row builders, and replace the wildcard package export with explicit leaf exports.
- decouple recommendation: keep pure notification contracts separate from local-outbox proof payloads so proof scaffolding cannot masquerade as contract ownership or runtime behavior.
- blockers: no audit blocker for writing this note; the implementation blocker is ownership overlap between contract files and proof fixtures, which should be separated before any cleanup or normalization work.
