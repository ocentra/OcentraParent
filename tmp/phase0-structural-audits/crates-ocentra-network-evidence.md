## Current Refresh Audit - 2026-06-19
- responsibility: this crate still owns deterministic packet/DNS/flow parsing plus proof-gated evidence assembly, but the live surface now also includes live-capture custody, platform readiness, adapter and lab proofs, browser/process correlation, local-AI queueing, platform claim manifests, risk budgeting, AI audit/detection, and signature-alert ingestion.
- dependencies: external dependencies remain minimal (`serde` only), but the internal dependency graph is wide and most user-facing behavior is assembled through the crate root and a network of cross-module proof wrappers.
- violations: `src/lib.rs` is still a broad public facade, several child modules act mainly as type and helper shims, and the docs summary still trails the observed owned surface.
- duplicated shapes: the same proof-envelope pattern repeats across `live_capture`, `live_capture_execution`, `raw_capture_storage`, `windows_firewall_lab_execution`, `windows_wfp_gate`, `linux_adapter_gate`, `android_vpn_service_gate`, `apple_network_extension_gate`, `action_result`, `platform_claims`, `signature_alert`, `screen_summary`, `risk_budget`, `ai_detection`, and `ai_audit`, especially the repeated `*_ref`, `*_refs`, `*_claimed`, `*_available`, and `*_authorized` fields.
- barrel/re-export/shim debt: `src/lib.rs` remains a mega-export surface, while `src/packet.rs`, `src/raw_capture_storage.rs`, `src/live_capture_execution.rs`, and `src/windows_firewall_lab_execution/mod.rs` continue to forward public types from deeper modules instead of exposing narrower owned entrypoints.
- schema drift: the crate name and older summary understate the current scope. The implementation now covers capture custody, platform gating, policy mapping, AI evaluation, and platform-claim normalization, so the observed domain is broader than the original parsing/replay framing.
- event/log/proof misuse: I did not see an event bus or structured runtime logging surface in this slice, but the proof structs carry boundary-enforcement flags and policy-authority bits that function as hidden control plane state. That makes the proof payloads harder to reason about than a narrower contract would be.
- test/proof structure issues: the proof modules are heavily integration-shaped, while the test structure is split between `src/tests.rs` and many focused unit files. The coverage surface is harder to scan than the implementation surface, and the umbrella test module adds another layer of indirection.
- dry_score: 33/100. The crate has real shared intent, but repeated normalization, repeated rejection checks, repeated artifact gating, and repeated proof-envelope fields keep the code from being genuinely DRY.
- dry_score_reasons: the dominant repetition is not just within one module family; it spans capture, adapter gates, lab execution, AI/reporting, and platform claims. The root facade and helper shims amplify that duplication by hiding the actual ownership boundaries.
- fix recommendation: extract the repeated proof-envelope shape into shared base types, keep the crate root to intentional public entrypoints, and consolidate the normalize/reject/artifact-gate helpers so the proof modules stop carrying parallel copies of the same validation logic.
- decouple recommendation: split parsing/replay from proof-gate orchestration, and split platform-gate construction from platform-claim aggregation. That would leave a smaller evidence core with thinner policy and platform wrappers over it.
- blockers: none for the refresh note itself. A real refactor will need a wide import audit and downstream test sweep because the crate root currently exposes most of the module tree.
