## Current Refresh Audit - 2026-06-19
- responsibility: Canonical custody contract boundary for data custody, retention, recovery handoff, source-of-truth, and hosting-policy schemas; the package is still the owner of contract shapes rather than runtime execution.
- dependencies: Allowed dependencies stay narrow (`@ocentra-parent/family-domain`, `@ocentra-parent/schema-domain`), but the package also mirrors concepts owned by `crates/storage-custody-core` and `packages/setup-domain`.
- violations: Scope is still too broad for one domain package because bundle taxonomy, recovery handoff, source-of-truth matrix, default locations, authorities, and hosting policy all live together; `package.json` also exposes a wildcard `./*` export surface that behaves like a broad package-level barrel.
- duplicated_shapes: Literal/object pairs repeat throughout `src/custody-boundary.ts` (`DataCustodyStateLiteral` + `DataCustodyState`, bundle state/type literals + parsed objects, handoff state/target literals + parsed objects, class ids, locations, authorities, hosting modes); matrix rows in `src/data-custody-matrix.ts` also duplicate the seeded class taxonomy.
- barrel_reexport_shim_debt: No TS re-export barrel is present, but `src/package-info.ts` is a thin identity shim and `package.json` wildcard exports widen the public surface more than the package needs.
- schema_drift: High drift risk between the seeded arrays/literals in `custody-boundary.ts` and the canonical rows in `data-custody-matrix.ts`; the package relies on parallel hand-authored taxonomies instead of one shared source for several repeated enums and row identifiers.
- event_log_proof_misuse: No runtime event or log misuse is visible in this package because it is schema-only, but the schemas are proof-adjacent and currently lack a dedicated proof artifact path, so contract assertions are being carried by unit tests alone.
- test_proof_structure_issues: Coverage exists under `tests/unit`, but `proofs/` is empty and there is no separate proof fixture or manifest for the custody invariants; that makes the package look test-backed but not proof-backed.
- dry_score: 43/100.
- dry_score_reasons: The package is deterministic and mostly schema-driven, which helps DRY, but it still repeats the same custody taxonomy in several literal/object forms, mixes multiple ownership concerns in one boundary, and keeps a broad export surface plus a shim that can hide future duplication.
- fix_recommendation: Collapse repeated custody enums and identifiers into one canonical contract source per concept, then keep `data-custody-matrix.ts` as a consumer of those primitives instead of a second taxonomy owner.
- decouple_recommendation: Split the shared custody primitives from the matrix/reporting layer, and move any setup/storage overlap into a smaller shared owner so this package only owns the custody contract vocabulary and validation.
- blockers: No blocker for this audit refresh. Cleanup work is blocked on aligning sibling owners before deleting any duplicated taxonomy, especially `crates/storage-custody-core` and `packages/setup-domain`.
