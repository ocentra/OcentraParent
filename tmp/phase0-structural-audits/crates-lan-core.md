- target_kind: Rust crate
- owned_paths: `crates/lan-core/**`
- declared_responsibility: LAN discovery and pairing decision flow plus event adapters into the child-domain protocol.
- observed_responsibility: Implements LAN discovery decisions, child-domain evidence/event helpers, and a typed `DomainEvent` bridge.
- should_own: LAN-specific decision logic, event adapter glue, and the small Rust-facing runtime surface for LAN discovery.
- should_not_own: Shared protocol string ownership, generic evidence contracts, or a crate-wide frontage shim.
- allowed_dependencies: `ocentra-eventing`, `ocentra-parent-agent-protocol`, `serde`.
- suspicious_dependencies: `ocentra-parent-agent-protocol` is used correctly as a boundary dependency, but the crate also invents local event/schema strings instead of consuming a shared protocol constant.
- expected_dependents: Rust tests, any runtime that emits LAN discovery events, and consumers of the LAN decision/event helpers.
- shared_contract_schema_usage: Relies on protocol event contracts and eventing types; no TS schema layer is present here.
- duplicate_or_near_duplicate_shapes: The LAN discovery intent/decision enums mirror the broader LAN contract vocabulary, and the local `lan_text_id!` wrapper duplicates branded string logic already handled elsewhere.
- id_name_status_drift: `LAN_DISCOVERY_DECISION_RECORDED_EVENT_TYPE` and `LAN_SCHEMA_VERSION` are crate-local names that look like shared protocol identifiers and should be centralized if they are intended to cross owners.
- direct_import_vs_event_boundary: Direct protocol/eventing imports are fine, but the event boundary is flattened by constructing contract strings locally instead of taking them from a canonical contract module.
- event_bus_usage: Yes; this crate implements `DomainEvent` and emits LAN discovery events.
- logging_and_proof_chain_expectations: No logger/trace adapter is visible in the core runtime surface, so proof-chain observability is currently implicit rather than explicit.
- boundary_violations: `pub use lan_pairing::*;` in `src/lib.rs` is a forbidden public re-export and turns the crate into a frontage shim.
- dry_common_core_candidates: Extract the string/id wrapper pattern, centralize LAN event constants, and keep the discovery decision model as the narrow owned core.
- dead_frontage_or_shims: `src/lib.rs` is a pure re-export shim.
- proposed_fix_packets: Remove the public re-export barrel, move shared event-type/schema constants into the protocol owner, and add a narrow trace/log adapter if this crate is meant to participate in proof chains.
- severity: high
- confidence: high
