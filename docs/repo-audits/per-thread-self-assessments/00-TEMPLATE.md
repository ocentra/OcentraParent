# Self-Assessment Template

Use this file only as the structure reference for each plan thread's own archival file.

Rules:
- Preserve your own report wording as the authoritative raw dump for this file.
- Do not rewrite from memory if you can paste from your own thread.
- Re-read your own thread before writing so earlier audit findings are not lost.
- If your latest report omitted something important from earlier audit passes, append it explicitly instead of dropping it.
- Do not analyze or fix product source in this pass.
- Do not mark the plan done.
- Keep the normalized header compact, then preserve the raw self-report below it.

```md
# <plan-thread-name>

## Normalized Header

- plan/thread name:
- source thread label:
- source thread id:
- worktree:
- branch:
- claimed status:
- claimed source files/crates/packages:
- claimed tests:
- claimed proof commands/artifacts:
- claimed blockers:
- claimed next actions:
- obvious missing evidence fields:
- archival note: self-report only; unverified input for structural review

## Raw Self-Report

Paste the thread's own report below this line with minimal alteration.
Prefer verbatim copy from the thread's self-assessment or completion architecture report.

## Optional Addendum

Only if needed:
- note any follow-up correction the same thread wants to append after rereading its own report
- do not silently replace the raw report; append instead
```
