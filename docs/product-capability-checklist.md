# Ocentra Parent Product Capability Checklist

This checklist is the fast lookup for "what do we have, what is in progress,
and what gap must be filled next?" It ties the user-facing product idea to
roadmap milestones, expectation files, and proof records.

Status terms come from [product-constitution.md](product-constitution.md).
The per-feature drill-down lives in [feature-list.md](feature-list.md). Feature
docs are the place for competitor pressure, gap detail, and next-AI checklists.

Current architecture authority is Rust-first. Product contracts, route
snapshots, actions, read models, and cross-boundary schema truth belong in
`crates/schema`, `crates/parent-runtime-core`, or the owning Rust domain/runtime
crate. TypeScript package references in this checklist are historical,
migration/debt, presentation-only, generated DTO consumer, thin-adapter, or
temporary edge-decoder references unless a current Rust-first workpack says
otherwise.

## Checklist Rules

- A row must move from `planned` to `in progress` only when a branch or merged
  slice has real contracts, runtime scaffolding, or proof work.
- A row must move to `done` only when the named scope is true for the named
  platform and validation evidence exists.
- A row that touches OS permissions, mobile entitlements, enforcement, remote
  relay, or child data custody must name manual proof requirements if CI cannot
  prove them.
- README summaries may use user-facing language, but this checklist must keep
  exact status honest.
