Purpose: keep the UI honest while the distribution route is still under proof.

## Research targets

- current parent portal routes and download entry states
- desktop launch, update, and rollback states
- Android and iOS provisioning / store states
- signing, notarization, and store claim language
- manual-required messaging for scaffold-only rows

## UI guidance

- Show the artifact, not a generic platform bucket.
- Show manual-required and preview-only states explicitly.
- Show setup handoff as a handoff, not a completed package claim.
- Keep child runtime distribution visually separate from parent client distribution.
