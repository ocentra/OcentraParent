# Decisions

Status: locked architecture decisions for the payment route.

| ID      | Decision                                                                                                           | Why it matters                                                                  | Follow-up                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| PSP-001 | Cloudflare Worker/API is the default billing control plane; do not split a second subscription plan.               | Matches low-volume control-plane traffic and the existing games pattern.        | Implement the Worker, Durable Object, D1, and Queue boundary.              |
| PSP-002 | Provider secrets, webhook secrets, and billing tokens stay server-side.                                            | Browser compromise must not become billing compromise.                          | Manage via Wrangler secrets or the Cloudflare secret store.                |
| PSP-003 | Provider is not product authority; app-owned ledgers decide entitlement.                                           | Providers can replay, delay, or partially fail events.                          | Ledger state must own all access transitions.                              |
| PSP-004 | Hosted checkout and hosted portal are the default parent billing UX.                                               | Keeps PCI scope and browser complexity down.                                    | Custom card capture stays out of scope unless a later proof justifies it.  |
| PSP-005 | Stripe is the default web subscription provider; Razorpay, PayPal, Apple, Google, and manual invoice are adapters. | Enables regional and surface-specific rollout without changing the core ledger. | Provider strategy and regional matrix must be explicit.                    |
| PSP-006 | Billing metadata must stay privacy-safe; no child data in provider metadata.                                       | Protects child and household data, and keeps provider payloads minimal.         | Dashboard and API contracts must redact aggressively.                      |
| PSP-007 | Starter bundle includes 1 parent portal and 1 child-device entitlement.                                            | Gives a usable default product without overcomplicating the first offer.        | Pricing docs must keep the bundle explicit.                                |
| PSP-008 | Paid extra child-device seats are monthly; default target price is $1/month.                                       | Makes seat expansion simple and predictable.                                    | Market or legal validation may adjust the target price.                    |
| PSP-009 | Referral invites are separate from household invites.                                                              | Avoids mixing family membership with growth mechanics.                          | Referral model tracks qualification and crediting separately.              |
| PSP-010 | Referral credits grant child-device entitlement only while the referred household remains qualified.               | Prevents permanent abuse of referral expansion.                                 | Losing qualification causes grace or blocked expansion, not data deletion. |
| PSP-011 | Signed EntitlementSnapshot is derived and device-bound; it is not the root of trust.                               | Trusted devices must gate consumption, not replace ledger truth.                | Device-trust-bootstrap-plan supplies the binding check.                    |
| PSP-012 | Regional provider adapters are mandatory before regional rollout.                                                  | Avoids shipping a US-only assumption globally.                                  | Market matrix must gate rollout order.                                     |

## Control-plane boundary

Cloudflare Worker/API is the default billing and entitlement control-plane boundary. It owns provider secrets, checkout/portal creation, webhook verification, idempotency, subscription projection, referral qualification, entitlement calculation, signed EntitlementSnapshot issuance, dashboard APIs, support/admin billing ops, reconciliation, and dead-letter handling. It must remain replaceable by a self-hosted Rust Billing API later, but desktop/mobile/browser clients must never own provider secrets or webhook truth.
