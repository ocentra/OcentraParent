# Decisions

Status: locked architecture decisions for the payment route.

| ID | Status | Decision | Why it matters | Follow-up |
| --- | --- | --- | --- | --- |
| PSP-001 | architecture-closed / implementation-open | `cloudflare-control-plane-plan` owns the shared `infra/cloudflare/` module; payment consumes it but does not own it. | Prevents payment docs from becoming shared infra truth. | WP00 handoff proof must exist before payment runtime work starts. |
| PSP-002 | architecture-closed / implementation-open | Provider secrets, webhook secrets, and billing tokens stay server-side. | Browser compromise must not become billing compromise. | Manage via shared Cloudflare secret custody. |
| PSP-003 | architecture-closed / implementation-open | Provider is not product authority; app-owned ledgers decide entitlement. | Providers can replay, delay, or partially fail events. | Ledger state must own all access transitions. |
| PSP-004 | architecture-closed / implementation-open | Hosted checkout and hosted portal are the default parent billing UX. | Keeps PCI scope and browser complexity down. | Custom card capture stays out of scope unless later proof justifies it. |
| PSP-005 | architecture-closed / implementation-open / provider-setup-required | Stripe is the default web subscription provider; Razorpay, PayPal, Apple, Google, and manual invoice are adapters. | Enables regional and surface-specific rollout without changing the core ledger. | Provider strategy and regional matrix must remain explicit. |
| PSP-006 | architecture-closed / implementation-open | Billing metadata must stay privacy-safe; no child data in provider metadata. | Protects child and household data, and keeps provider payloads minimal. | Dashboard and API contracts must redact aggressively. |
| PSP-007 | architecture-closed / implementation-open | Starter bundle includes 1 parent portal and 1 child-device entitlement. | Gives a usable default product without overcomplicating the first offer. | Pricing docs and proof must keep the bundle explicit. |
| PSP-008 | architecture-closed / implementation-open / sujan-decision-required | Paid extra child-device seats are monthly; default target price is $1/month. | Makes seat expansion simple and predictable. | Market or legal validation may adjust the target price. |
| PSP-009 | architecture-closed / implementation-open | Referral invites are separate from household invites. | Avoids mixing family membership with growth mechanics. | Referral model tracks qualification and crediting separately. |
| PSP-010 | architecture-closed / implementation-open / sujan-decision-required | Referral credits grant child-device entitlement only while the referred household remains qualified. | Prevents permanent abuse of referral expansion. | Losing qualification causes grace or blocked expansion, not data deletion. |
| PSP-011 | architecture-closed / implementation-open | Signed `EntitlementSnapshot` is derived and device-bound; it is not the root of trust. | Trusted devices must gate consumption, not replace ledger truth. | `device-trust-bootstrap-plan` supplies the binding check. |
| PSP-012 | architecture-closed / implementation-open / provider-setup-required | Regional provider adapters are mandatory before regional rollout. | Avoids shipping a US-only assumption globally. | Market matrix must gate rollout order. |
| PSP-013 | architecture-closed / implementation-open / sujan-decision-required / provider-setup-required | Regional provider rollout order is documented but not product-closed. | Launch order affects setup, support, and payment visibility. | Mirror order and blockers into proof and route docs. |
| PSP-014 | architecture-closed / implementation-open / manual-required | Parent dashboard and support/admin field boundaries are documented but not runtime-proven. | Prevents child/private data leakage. | Keep allow/deny lists synchronized with proof. |
| PSP-015 | architecture-closed / implementation-open / sujan-decision-required | Referral qualification and anti-abuse thresholds are documented but not business-approved or proven. | Abuse thresholds alter entitlement and support behavior. | Approval and proof remain required. |
| PSP-016 | architecture-closed / implementation-open / legal-tax-required | Tax, refund, dispute, cancellation, and grace policies are documented but not legal/tax-closed. | Monetary and entitlement changes require exact policy. | Legal/tax approval and proof remain required. |
| PSP-017 | architecture-closed / spec-complete / runtime-open | Rollout proof matrix, route gate, and exact assertion scope are documented but not fully proven. | Prevents docs-only closure from being confused with runtime proof, while still requiring the spec to be exhaustive. | Route docs, proof paths, assertion matrix, and handoff proof must agree. |
