# Network Flow Evidence Expectations

Network flow evidence helps detect activity that is not obvious from browser,
app, or window evidence alone. The Rust agent may observe network metadata,
derive summaries, and give AI/policy an evidence-backed digest. AI does not sniff
traffic, inspect packets, or decrypt content.

The focused implementation architecture lives in
[Network Flow Evidence Capture Architecture](../architecture/network-flow-evidence-capture.md).
The full-scope evidence, intervention, proof, UI, and workpack package lives in
[Network Plan](../plans/network-plan/README.md).
Network event routing depends on the
[Reusable Rust Eventing Plan](../plans/eventing-plan/README.md).

## Outcome Bar

Parent outcome:

- A parent can see which apps/processes are communicating over the network.
- A parent can see top destinations, domains where available, IPs, ports,
  protocols, connection counts, and bandwidth/time summaries where available.
- A parent can see unusual or bypass-like indicators such as VPN, proxy, Tor,
  tunnel adapters, unknown high-volume processes, or new destinations.
- A parent can distinguish domain-known, IP-only, process-attributed,
  process-unknown, encrypted-content-unavailable, and adapter-unavailable states.

Child-device outcome:

- The Rust agent records normalized network flow metadata into the encrypted
  journal and SQLite query store.
- The Rust agent derives queryable flow summaries and AI-readable digests from
  stored evidence.
- AI reads only stored flow evidence or summaries. AI does not capture, sniff, or
  decrypt network traffic.
- Policy/enforcement consumes typed flow summaries and parent rules, not raw
  packet dumps.

## Data Scope

Network flow evidence may record:

- Process id, process name, executable path, publisher/signature/hash where
  available.
- Local IP, local port, destination IP, destination port, protocol, TCP state,
  and timestamps.
- Domain/DNS attribution where available, including IP-only and unknown states.
- Connection count, first seen, last seen, duration, and bytes sent/received
  where the adapter can provide them.
- Network adapter/interface hints, VPN/proxy/tunnel indicators, and route type
  where available.
- Flow summary rollups: top processes, top domains, top IPs, high-volume flows,
  new destinations, repeated failures, and unusual background traffic.

Network flow evidence must not record unless a later milestone explicitly
approves a stricter legal/privacy/security boundary:

- Decrypted HTTPS payloads.
- Full page URLs from packet metadata.
- Request/response bodies.
- Chat/message content.
- Search terms, form values, cookies, tokens, or credentials.
- Raw packet dumps as the normal evidence store.

## Trust Boundary

- Network adapters observe flow metadata and return typed observations.
- DNS/domain attribution is a best-effort evidence field, not a page/content
  claim.
- The Rust agent writes raw flow observations and derived summaries locally
  before portal, AI, policy, or enforcement consumes them.
- AI consumes flow evidence references or structured digests generated by the
  agent. AI output may classify unusual, likely game, likely VPN/proxy, or
  unknown states, but cannot invent destinations, bytes, duration, or process
  ownership.
- Browser URL/tab evidence remains the source of exact URLs. Network flow
  evidence may support that evidence but must not replace it.

## Expected Deliverables

- Network flow observation contract.
- DNS/domain attribution status contract.
- Process-to-flow attribution contract.
- Flow counter and bandwidth summary contract where supported.
- VPN/proxy/tunnel indicator contract.
- Network digest contract for AI/policy consumption.
- Network event contracts for typed local flow, summary, alert, detection,
  audit, policy, command, and adapter-result routing, implemented on the
  reusable Rust eventing crate rather than a network-only bus.
- Analyzer alert contract for Zeek-style summaries and Suricata/Snort-compatible
  signature alerts where those inputs are used.
- AI detection and AI audit report contracts for structured summaries, evidence
  refs, uncertainty, recommendations, and unsupported-claim rejection.
- Risk budget and cascade threshold contract before household risk budgets can
  influence network-derived policy output.
- Query-store read model for recent flows, top processes, top destinations,
  high-volume activity, and unusual destinations.
- Portal recent network activity and unusual-traffic view.
- Tests for IP-only, domain-known, process-unknown, adapter-unavailable,
  encrypted-content-unavailable, and unusual-flow states.

## Runtime Flow

```text
network flow observations
  -> encrypted journal
  -> SQLite query store
  -> flow summaries and unusual-traffic digest
  -> optional AI classification for unknown/unusual evidence
  -> deterministic policy evaluator
  -> enforcement adapter or permission request
  -> auditable parent-visible result
```

The common unusual-network path should be:

1. Rust agent observes a process opening network flows.
2. Rust agent stores flow metadata and updates flow summaries.
3. Rust agent marks known states deterministically where possible, such as
   process-attributed, domain-known, IP-only, high-volume, new destination, or
   VPN/proxy/tunnel indicator.
4. AI may classify only the stored digest, for example likely VPN/proxy, likely
   game traffic, normal update traffic, unusual unknown process, or ask-parent.
5. Policy evaluator checks parent network, app, category, VPN/proxy, and time
   rules.
6. Enforcement, when enabled, blocks/terminates only after a typed policy
   decision references stored flow evidence.
7. Parent portal shows the evidence, summary, classification, rule, action, and
   result.

## Acceptance

- The system can distinguish exact browser URL evidence from network flow
  evidence.
- Network flow summaries are generated from stored journal/query evidence, not
  portal state or AI guesses.
- AI input references stored flow evidence and summaries; AI cannot scan packets,
  decrypt content, or invent traffic.
- Unknown or encrypted traffic remains unknown/IP-only/unavailable unless there
  is explicit evidence for a stronger claim.
- Parent-visible reports can show top processes, destinations, bytes/counts where
  available, VPN/proxy/tunnel indicators, and unusual-flow states.
- Policy can consume a flow summary or unusual-network digest in dry-run before
  enforcement is enabled.
- Analyzer alerts, AI audit narratives, and risk budgets cannot authorize
  enforcement without typed policy decisions, parent rules, adapter proof, and
  audit.

## Done Signal

A local run records real process-attributed network flow metadata into the
journal and query store, derives a queryable network digest, makes that digest
available to AI/policy with evidence references, and does not claim exact URLs or
decrypted content from flow metadata.
